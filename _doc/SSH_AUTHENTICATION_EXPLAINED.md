## 🔍 问题的真正原因

### 不是"密钥不同"，而是"SSH 客户端不同"

#### 场景 1：系统 SSH（成功）
```powershell
# 使用系统 SSH
ssh -T git@github.com

# SSH 客户端：C:\Windows\System32\OpenSSH\ssh.exe
# 私钥位置：~/.ssh/id_rsa
# 结果：✅ 认证成功
```

#### 场景 2：Git Bash SSH（失败）
```powershell
# Git 默认使用的 SSH
git push origin main

# SSH 客户端：C:\Program Files\Git\usr\bin\ssh.exe (Git Bash)
# 问题：
#   1. Git Bash 的 SSH 可能没有正确配置
#   2. 或者密钥权限设置不正确
#   3. 或者找不到密钥文件
# 结果：❌ Permission denied (publickey)
```

### SSH 密钥 vs SSH 客户端

## 🔑 SSH 密钥的作用

### 不是"加密"，而是"身份验证"

#### SSH 密钥对的工作原理

```
┌─────────────┐                    ┌─────────────┐
│   你的电脑   │                    │   GitHub    │
└─────────────┘                    └─────────────┘
       │                                   │
       │ 私钥 (id_rsa)                     │ 公钥 (id_rsa.pub)
       │ - 保密                            │ - 公开
       │ - 用于签名                        │ - 用于验证
       │                                   │
       │ 1. 用私钥对数据签名                │
       ├──────────────────────────────────>│
       │                                   │
       │                    2. 用公钥验证签名
       │                       如果验证通过，说明：
       │                       - 签名者拥有对应的私钥
       │                       - 签名者就是你（身份确认）
       │                                   │
       │ 3. 认证成功                        │
       │<──────────────────────────────────┤
```

### 关键概念

1. **私钥**：
   - 保存在你的电脑上
   - 用于对数据进行"签名"
   - 绝对不能泄露

2. **公钥**：
   - 上传到 GitHub
   - 用于"验证"签名
   - 可以公开分享

3. **认证过程**：
   - 你用私钥签名
   - GitHub 用公钥验证
   - 验证通过 = 身份确认

## 🛠️ 环境变量的作用

### 不是"调整密钥"，而是"指定 SSH 客户端"

#### 问题场景

```powershell
# Git 默认行为
git push origin main
# ↓
# Git 调用：Git Bash 的 SSH
# ↓
# Git Bash SSH 尝试读取密钥
# ↓
# ❌ 失败：找不到密钥或权限问题
```

#### 解决方案

```powershell
# 设置环境变量
$env:GIT_SSH = "C:\Windows\System32\OpenSSH\ssh.exe"
# ↓
# Git 调用：Windows OpenSSH
# ↓
# Windows OpenSSH 读取密钥
# ↓
# ✅ 成功：找到密钥并正确使用
```

## 📝 准确的理解

### 正确的表述应该是：

> "当 Git 尝试 push 到远程仓库时，Git 会调用 SSH 客户端进行身份验证。SSH 客户端使用本地的私钥对数据进行签名，GitHub 使用对应的公钥验证签名。如果验证通过，说明操作者拥有私钥，身份得到确认，允许推送。
>
> 刚才的问题是：Git 默认使用的 SSH 客户端（Git Bash 的 SSH）没有正确配置或找不到密钥，导致认证失败。通过设置环境变量，我们让 Git 使用 Windows 系统自带的 OpenSSH，它有正确的密钥配置，所以认证成功。"

## 🔍 深入理解

### SSH 认证 vs 加密

| 概念 | SSH 的作用 | 说明 |
|------|-----------|------|
| **身份验证** | ✅ 主要作用 | 证明你是谁 |
| **数据加密** | ✅ 附加作用 | 保护传输安全 |
| **数据完整性** | ✅ 附加作用 | 防止篡改 |

### SSH 密钥 vs TLS/SSL 证书

| 对比项 | SSH 密钥 | TLS 证书 |
|--------|---------|---------|
| **用途** | 身份验证 | 身份验证 + 加密 |
| **信任模型** | 你自己信任 | 第三方 CA 信任 |
| **有效期** | 永久（除非手动撤销） | 有期限 |
| **使用场景** | Git、服务器登录 | HTTPS 网站 |
